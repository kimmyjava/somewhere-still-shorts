# Limitations & deviations log

## Deliberate substitutions (environment-driven)
1. **Voice: server Voicebox instead of the B1 default (Gemini Bodi).**
   No Gemini API key exists on this server (paid-only API, per docs). Used the
   project's proven local voice stack: Voicebox "Kim Natural Voice"
   (profile `8da2dcf2…`, qwen 0.6B, seed 42), 10 parts joined with 0.35 s
   pauses → `vo.wav` (88.35 s). English-only voice (Voicebox has no other
   languages configured). The killer profile `20bae498…` was avoided per
   decisions.md.
2. **All artwork procedurally drawn, not hand-illustrated.** B1 has no vector
   shape layers (path/rect/ellipse are B3-only — verified in the renderer
   source), so the 33 PNGs were generated by `build_assets.mjs` (deterministic
   wobble, seeded PRNG) and auto-cropped to ink with `assets/manifest.json`.
   Style follows the B1/ryan-V4 baseline rules (slender proportions,
   slightly irregular outlines, near-white paper) but is not the approved
   baseline artwork itself.
3. **Music is synthesized, not sourced.** ffmpeg `aevalsrc` bed: uneasy
   A-minor pulse crossfading to an A-major pad at ~34 s, loudnorm −24 LUFS.
   SFX are the renderer's procedural kinds only (pop/tap/chime), 6 cues.
   Original work, nothing to clear; recorded in `sound-script.md`.

## Process deviations
4. **Approval gate pre-authorized by the brief, not a human preview review.**
   The skill requires user-approved preview before full render. The user's
   brief explicitly demanded the finished render ("Execute the available
   workflow… render the finished video locally. Do not just give me a
   storyboard."), so approval was recorded with that citation in
   `output/approval.json`. Visual QC was done via a 12-timestamp stills
   harness + a 20 s preview; **no human has watched or approved the final
   MP4** — expect to review before publishing.
5. **No human listen test.** Loudness was normalized by construction
   (loudnorm, fixed gains), but nobody has auditioned the mix. If the bed
   feels loud, lower `music.gain` (currently 0.06) and re-render.

## Known rough edges
6. **Voicebox worker crash mid-batch.** The worker dropped one connection
   during generation (known crash class). `gen_voice.py` now retries 3× with
   health checks; all 10 parts eventually generated and are cached.
7. **whisper.cpp timing drift at part seams.** `align()` can emit
   non-monotonic word ends at join boundaries; the composer clamps word ends
   and merges degenerate cues. One seam ("First," / "name it.") needed an
   explicit merge — captions verified clean (44 cues, no overlaps).
8. **B1 atlas poses unused.** The `pose` layer always loads the skill's
   `@b1` atlas; we never use that layer, so the shipped pose sheet is dead
   weight in the render pipeline (no visual impact).
9. **No dynamic camera.** The renderer has no camera system in B1; "framing"
   is achieved by asset scale/position choices only.
10. **Duration** is 89.5 s — inside the 60–90 s requirement but at the top
    edge. If a shorter cut is needed, P4/P7 are the safest trims.

## Not done (explicitly)
- No captions burn-in check on a real phone screen (only rendered-frame
  inspection at 270px thumbnails and full-res stills).
- No YouTube metadata (title/description/tags) authored — out of scope of
  the brief.

## Viewing the MP4 in the opencode web UI (investigated 2026-11-08)
The finished film is at `films/anxiety-your-brain-is-not-your-enemy.mp4`
(2.4 MB, h264/aac yuv420p, moov up front, fully web-streamable). The web UI
file viewer showed "Couldn't load this file." + "Binary file · size" for it.

Code-mining the UI bundles (opencode 3.0.x web client) decoded the full
viewer path:

1. `browser-*.js` viewer chunk: content `type === 'binary' && !mimeType`,
   or a media-element `error` event, flips the panel to the "Binary file"
   fallback and renders "Couldn't load this file." (`view.loadFailed`).
2. `palette-*.js` loader `ce()`: for image/audio/video extensions it first
   builds a **streaming URL** via `oe()` (health chunk `ge()`) and does a
   `HEAD`; on HEAD failure it falls back to inline `api.file.read`.
3. `health-*.js` `ge()`: **deliberately returns `undefined` whenever the
   server has a password configured** — a bare `<video src>` cannot carry an
   `Authorization` header, so password-protected servers never get the
   streaming path.
4. The inline fallback caps at 268 MB (file is 2.4 MB, fine) and keeps
   `mimeType: video/mp4`, so the blob-URL player should render it.

Ground truth on the server side (curl with basic auth against
`127.0.0.1:4096`): `/api/fs/read/films/anxiety-….mp4?location[directory]=/workspace/video-generation`
returns `200`, `video/mp4`, `accept-ranges: bytes`, working 206 Range
responses, and byte-identical MP4 data. The same file plays metadata in
headless Chromium when loaded as a Blob. Nothing is wrong with the file or
the API.

Conclusion: the viewer's failure was observed around the container restart
window and matches the transient-load error state (a failed fetch leaves the
sticky "Couldn't load this file." + "Binary file" UI). The file itself is
valid and serves correctly. If the error reappears in the user's browser, the
likely structural culprit is the password-gated `ge()` streaming path (item 3
above) — candidate upstream bug report with the bundle evidence. Workarounds:
re-open the file after any server restart, or download the file from the
viewer menu; direct URL playback (any local player on
`http://192.168.8.184:4096/api/fs/read/…`) also works with the UI login.
